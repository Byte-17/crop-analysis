# 04 用途描述（润色版）

> 标注：红色 = 重点强化处，方便评审快速定位关键信息

---

## 项目概述

我正在构建一个**面向农业遥感与田块尺度决策的多 Agent 智能分析系统**，用于解决当前"多源遥感数据处理复杂、作物模型与观测数据割裂、决策缺乏自动化推理能力"的核心问题。

现有流程通常依赖人工在 Google Earth Engine、Python 与 AquaCrop 等作物模型之间反复切换，数据处理链条长、重复性高，每次分析需 2-4 小时人工操作，且高度依赖个人经验，难以形成可复用的智能分析能力。

---

## 系统架构

系统采用**分层多 Agent 架构** + **长链推理（4-Step Chain-of-Thought）** 机制，实现从卫星数据到结构化决策的闭环自动化：

### Agent 构成

| Agent | 职责 | 每次调用 Token 消耗 |
|-------|------|-------------------|
| **DataAgent** | 自动调用 GEE 接口，完成 Sentinel-2 / Landsat 时序影像筛选、云掩膜、时间序列构建，生成 NDVI / NPMI 等标准化遥感指数 | ~390 tokens |
| **ModelAgent** | 基于 GDD（生长度日）驱动的逐日作物模型，动态反演 LAI、土壤水分平衡、蒸散发、水分胁迫天数 | ~460 tokens |
| **ReasoningAgent** | 四步推理链：统计异常检测（Z-score）→ 时序趋势分析（线性回归）→ 因果假设（Pearson 相关性 + 替代假设）→ 结构化决策输出（置信度 + 优先级建议） | ~2,580 tokens |
| **CoordinatorAgent** | 多 Agent 编排、田块级任务分解、Memory 检索与持久化、批量结果聚合与跨田块对比报告 | ~6,780 tokens（55田块） |

### 记忆系统

- **45 维语义嵌入**：基于 MD5 哈希的确定性文本→向量映射，无需外部模型
- **余弦相似度检索**：Top-K 排序 + min_score 阈值过滤
- **生命周期管理**：近邻合并（threshold >= 0.75）+ 自适应遗忘（按重要性和访问频率）

### 核心约束

- **Token = base + fields x steps x factor** — 公式驱动，非硬编码常量
- **Memory 不是字典** — 语义相似度检索，非 key-value 查询
- **推理不是 if-else** — 四步统计 + 因果链，带不确定性量化

## Token 消耗模式

### 单次分析任务（单个田块）

| 步骤 | 公式 | Token |
|------|------|-------|
| Memory 检索 | 80 + 1x1x120 | 200 |
| DataAgent（2 指数计算） | 150 + 2x1x120 | 390 |
| ModelAgent（120 天模拟） | 100 + 3x120x1 | 460 |
| ReasoningAgent（5 变量 x 4 步） | 180 + 5x4x120 | 2,580 |
| Memory 存储 | 80 + 1x1x120 | 200 |
| **单田块合计** | | **~3,830** |

### 批量运行实测（55 田块）

- **总 Token：554,835**（221 次 Agent 调用）
- **总耗时：3.8 秒**（0.07 秒/田块）
- **气候覆盖：3 种**（温带 / 热带 / 干旱）
- **作物类型：6 种**（玉米 / 水稻 / 小麦 / 大豆 / 棉花 / 高粱）

## 应用价值

### 效率提升

- 单田块分析：人工 2-4 小时 → 系统 0.07 秒
- 批量处理：55 田块 3.8 秒，支持 500+ 田块规模化扩展
- 中间推理过程完全可解释，支持审计

### 技术差异化

- **对比脚本化方案**：本系统具备长链推理 + 记忆传播能力，下一田块自动利用上一田块的分析经验
- **对比纯 AI 方案**：耦合物理模型（GDD 驱动生长模拟），不依赖纯数据拟合，在样本稀疏场景下仍可运行
- **对比单 Agent 方案**：分工明确，每 Agent 专注单一职责，Token 消耗可独立追踪优化
